# FIELD NETWORK PLAYER EXPERIENCE PLAN — 2026-08-25

Planning baseline assembled from shipped Mortis terminology. Not a canon document.
Nothing here invents factions, history, characters, or restricted ranks.
Display names use `neutral_fallback` unless a prior owner stamp exists.

## Surface relationship (unchanged)

- VRChat = what players witness
- Registry / terminal = what players can verify
- Mortis Field Network / Discord = what players hear
- Archive = what players can investigate

Discord remains the least authoritative surface. Incomplete or contradictory
traffic is allowed. Discord is not a canon database.

## First-time player path

Assume the player knows nothing.

1. Arrives in ARRIVAL. Sees NOTICE, CONDUCT AND TERMS, ENTRY, HOW TO BEGIN.
2. Reads HOW TO BEGIN (also `/orient`).
3. Accepts CONDUCT AND TERMS.
4. Completes ENTRY (callsign). Receives the Initiate presentation mark.
5. NETWORK and FIELD become visible. STAFF does not.
6. REFERENCE answers functional questions. Not an archive of record.
7. SUPPORT DESK opens a private ticket. Categories: general, report, appeal, accessibility.
8. WORLD ACCESS holds world-join information. Discord does not adjudicate what was witnessed.

Feeling to preserve: *I entered something that already existed before me.*
No lore dump. No progress track. Locked names are names, not invitations.

## FAQ (player-safe, shipped as `tpl.network.reference`)

Answered functionally. If source material does not define an answer, stay
neutral or mark NONCANON_PROPOSAL. Do not invent.

| Question | Where |
|---|---|
| How do I get started? | HOW TO BEGIN |
| What should I do first? | CONDUCT AND TERMS → ENTRY → NOTICES |
| How does communication work? | OPEN CHANNEL (in-character), QUESTIONS (clear), NOTICES (posted) |
| Basic conduct? | CONDUCT AND TERMS |
| Tickets? | SUPPORT DESK, private, report/appeal OWNER+OPERATIONS only |
| Help? | SUPPORT DESK or QUESTIONS |
| Approved information? | Terminal / Internal Network verifies. RECORDS re-presents published player-safe material. |
| Missed a notice? | Not a hidden exam. Ask, or open a ticket. |
| Discord / world / terminal? | Witness the world. Verify on the terminal. Hear traffic here. |
| Something went wrong? | SUPPORT DESK. If arrival is closed, wait for a further notice. |

World-content proposals are not taken in tickets.

## Structure (blueprint keys — never names)

ARRIVAL public: `arrival.notice`, `arrival.terms`, `arrival.intake`, `arrival.guide`
NETWORK initiate+: `network.dispatches`, `network.status`, `network.traffic`, `network.queries`, `network.reference`
OPERATIONS, RECORDS, FIELD, COMMUNITY, SUPPORT as already blueprinted.
STAFF is staff-only.

No streamer / content-creator / YouTuber roles. No restricted rank ladder.

## Onboarding

Default channels: NOTICE, CONDUCT AND TERMS, ENTRY, HOW TO BEGIN.
Manual Discord Safety Setup remains operator-side (API-gated).
Gateway has no privileged intents. Interactions Endpoint URL stays blank.

## Tickets

Rate limit: two open tickets per opener.
Reopen is staff-only and counts against the rate limit.
Opener text with restricted terms is held for staff; original does not post.
Ticket channels are not blueprint player-facing objects.
Live Discord web-open requires a real member snowflake. Demo handles are simulator-only.

## Operational notices

Allowed through dispatch only: maintenance, outage, deployment, lockdown, signed application updates.
NARRATIVE events stop at ELIGIBLE — AWAITING ENACTMENT.

## Health

Report-only: missing channels/roles, topic drift, webhook missing, lockdown, gateway not ready, pin template missing.
Destructive cleanup remains constrained. Orphans with history are never deleted.
